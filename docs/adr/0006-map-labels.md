# ADR-0006: オフライン地図に地名・道路名のテキストラベルを表示する

- ステータス: Accepted
- 日付: 2026-07-28
- プロジェクト: tendenko

## コンテキスト

iOS シミュレータで実際にアプリを起動し UI を確認したところ (ADR-0003 の「app/ でのオフライン地図表示」を実機で追体験)、地図には道路網・海岸線・浸水想定オーバーレイの線は出るが、地名も道路名も一切表示されず、現在地と目的地の関係が地図から読み取れないことが判明した。避難アプリという性質上、「今どこにいて、どこに向かえばよいか」を地図から即座に読み取れないのは本末転倒であり、FR-15 (縮退モード) 以前の基本的な可読性の欠落と言える。

原因を調査した結果、2 つの層に分かれることが分かった。

1. **`app/Tendenko/MapView.swift` のスタイル定義 (`OfflineMapStyle.swift`) にテキストを描画する symbol レイヤーが定義されていない**。background/landuse/water/buildings/roads の塗り・線レイヤーのみで、`glyphs` (フォントグリフ配信 URL) の設定も無い。MapLibre (どの地図ライブラリも共通) はテキストラベルの描画に `{fontstack}/{range}.pbf` 形式の事前生成グリフが必須で、これが未設定だと symbol レイヤーを足してもテキストは描画されない
2. **タイルデータ自体には地名・POI 名が既に含まれている**。tilemaker は `-config`/`-process` に OpenMapTiles 互換の既定スキーマ (`config-openmaptiles.json` / `process-openmaptiles.lua`、pipeline は素の既定値を使用) を使っており、生成される `tiles-<mesh>.mbtiles` には `place`, `poi`, `transportation_name`, `water_name` 等のレイヤーが最初から入っている。同梱サンプル (釜石 584177) の実タイルを解析し、`浜町二丁目`・`釜石市`・`ホテルシーガリアマリン` 等の実地名・POI 名が生データとして存在することを確認済み

つまり **pipeline (Go)側・地域パッケージフォーマット (ADR-0003) は変更不要**で、app 側のスタイル定義とオフラインでのグリフ配信の実装だけが欠けている、という比較的小さいスコープの話である。

## 検討した選択肢

### 選択肢 A: CJK フォント (Noto Sans JP 等) のグリフ PBF を全レンジ生成しアプリに同梱、ローカル配信

`MBTilesServer` (127.0.0.1 でローカル HTTP 配信、ADR-0003 追記 2026-07-20) と同じパターンで `GlyphServer` を実装し、`glyphs` URL を `http://127.0.0.1:<port>/fonts/{fontstack}/{range}.pbf` に向ける。フォント自体はアプリ本体に 1 回だけ同梱すればよく (地域パッケージには含めない)、地域が増えても追加コストは無い。

- ✅ 常用漢字外の稀な地名 (難読地名・小字) も含め文字化け (豆腐) の心配がない
- ✅ 生成は一度きりで、以降は保守対象が増えない (個人開発の運用時間と相性が良い ── ADR-0003 と同じ判断軸)
- ❌ アプリバイナリのサイズが恒久的に増える (フルセットで概算 10〜15MB程度、要実測)
- ❌ フォントのライセンス確認が要る (候補は OFL 系が多いが、配布元・バージョンを推測せず確認してから使う)
- 判定: 採用

### 選択肢 B: 常用漢字 + かな + 英数字だけにサブセットしたグリフを自前生成

- ✅ サイズを大幅に削減できる (数 MB程度)
- ❌ サブセット基準 (常用漢字表だけで日本の地名を本当に網羅できるか) の検証が要り、対象外の文字が出た地域で無言の文字化けという事後発覚しにくい不具合を生む。避難時に読めない地名が出ることは許容できない
- ❌ サブセット生成・維持のためのツールチェーンを自作することになり、選択肢 A に対して複雑さが増える割にサイズ以外のメリットが薄い
- 判定: 棄却

### 選択肢 C: テキストラベルを描画せず、現在地・避難所名などを SwiftUI オーバーレイの UI 要素 (バッジ等) として個別に出す

- ✅ グリフ配信の複雑さを完全に回避できる
- ❌ 地図自体は依然として地名の読めない状態のままで、今回発覚した「地図として何を見ているか分からない」という問題の根本解決にならない。ユーザーが求めているのは地図上のテキスト情報であり、個別 UI 要素での代替は要望と食い違う
- 判定: 棄却 (ただし現在地・目的地の強調表示は選択肢 A と併用する形で別途あってよい)

## 決定

選択肢 A を採用する。CJK 対応フォントのグリフ PBF をアプリに同梱し、`MBTilesServer` と対になる `GlyphServer` をローカルに立てて配信する。スタイル定義には少なくとも次の symbol レイヤーを追加する。

- `place` レイヤー: 地名ラベル (市区町村・町丁目)。ズームレベルに応じた `filter`/`text-size` の出し分けが必要 (低ズームで全部出すと過密になる)
- `transportation_name` レイヤー: 主要道路の名前 (線に沿った配置)
- 避難所名 (`region-<mesh>.sqlite` の `shelters` テーブル) は既存データなので、地図タイルの POI とは別に、目的地強調表示として重ねられないか合わせて検討する

## 帰結

- **フォントの配布元・ライセンスの一次情報確認**が実装前に必要 (URL を推測しない方針、ADR-0003 の A40/福井県データ調査と同じ手順)。候補や実測サイズは次の着手時に確認する
- `GlyphServer` の実装は `MBTilesServer` (`app/TendenkoStorage/` 配下) と同じ `NWListener` パターンを踏襲できる見込みで、既存実装の再利用性が高い
- スタイル変更 (`OfflineMapStyle.swift`) は次優先タスクの「経路の可視化」(MapView に経路線・浸水フラグの色分けを描画する作業) と同じファイルを触るため、**同一セッションでまとめて着手するのが効率的**。次セッションのタスク順の差し込みはこの ADR とは別に検討する
- 未解決: ズーム別のラベル密度・優先順位 (どの地名/POIを残すか) は実装時に実データで確認しながら調整する。全国 2,515 パッケージの地名密度は都市部と地方で大きく異なるため、都市部 (例: 東京都心 533946) でのラベル過密も実装時に確認する

## 追記 (2026-07-28): 実装・実機確認

同日中に実装した。

- **フォント**: [openmaptiles/fonts](https://github.com/openmaptiles/fonts) v2.0 リリース (`noto-sans.zip`) から `Noto Sans Regular/` (256 レンジファイル、34MB) のみを採用。README に「All fonts are either licensed under OFL or Apache」と明記されており、Noto Sans は SIL OFL 1.1 (アプリへの組込み・再配布可、フォント単体の販売のみ不可)。Bold は当面不要と判断し同梱しない (docs/licenses.md に追記)
- **タイルのプロパティ名を実データで確認**: tilemaker の既定 `process-openmaptiles.lua` は `preferred_language = nil` のため、`SetNameAttributes()` が地名を `name` ではなく `name:latin` というキーに書き込む (関数名に反して実際には元言語 = 日本語のテキストがそのまま入る)。`mapbox-vector-tile` で釜石メッシュの実タイルを protobuf レベルでデコードし、`place`/`transportation_name`/`poi` レイヤーの実プロパティが `{'class': 'neighbourhood', 'name:latin': '浜町二丁目'}` のような形であることを確認してから実装した。ここを見落とすと symbol レイヤーの `text-field` が常に空文字になり、レイアウトは効いているのにテキストだけ出ないという気づきにくい不具合になっていた
- **`GlyphServer`** (`app/TendenkoDomain/Sources/TendenkoStorage/GlyphServer.swift`): `MBTilesServer` と同じ `NWListener` パターンで実装。パスは `/fonts/{fontstack}/{range}.pbf` (fontstack はパーセントデコード)。TDD でテスト (`GlyphServerTests.swift`) を先に書いてから実装。`make domain-test` で確認 (65 件パス)
- **`OfflineMapStyle.swift`**: `glyphs` に `http://127.0.0.1:<port>/fonts/{fontstack}/{range}.pbf` を設定。`place` (地名、ズームに応じた `text-size` 補間) と `transportation_name` (道路名、`symbol-placement: line`、minzoom 12) の symbol レイヤーを追加。避難所名の強調表示 (「帰結」で触れた案) は今回のスコープ外のまま次回検討とする
- **`project.yml`**: フォントディレクトリは 256 ファイルの階層を保持する必要があるため `type: folder` (folder reference) でバンドルに含めた。個別ファイル参照だと Xcode がバンドルルートにフラット化してしまい `<fontstack>/<range>.pbf` の相対パスが壊れる
- **動作確認 (iOS シミュレータ)**: 釜石メッシュのサンプルデータで「箱崎町」「本州」等の地名ラベルが正しい日本語グリフで描画されることをスクリーンショットで確認した (文字化け・豆腐なし)
- **未確認のまま残る点**: 道路名 (`transportation_name`, 例: 「国道45号」) は今回のビューポートに主要道路が入らず未確認。都市部でのラベル密度・過密の調整も引き続き未着手
