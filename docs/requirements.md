# 津波避難アプリ 要件定義書

- 版: v0.1 (ドラフト)
- 作成日: 2026-07-18
- ステータス: MVP スコープ確定 / 詳細設計前

---

## 1. プロダクトの目的

**災害時、津波情報をトリガーに高台への避難を最短化する。**

最短化の対象は以下の 3 つの時間の合計とする。

| フェーズ | 定義 | 短縮アプローチ |
|---|---|---|
| T1: 気付くまで | 警報発表 → 端末が鳴る | 低遅延プッシュ / 通知強度の最大化 |
| T2: 判断 | 鳴る → 歩き出す | ゼロ操作 UI。開いた瞬間に方向と目的地が確定済み |
| T3: 移動 | 歩き出す → 高台到達 | 迷わない経路 / 音声主体の案内 / 即時リルート |

設計原則: **発災時のユーザー操作はゼロ。** 設定・選択・確認はすべて平時に済ませる。T2 が最大のボトルネックであり、選択肢を提示する UI は導入しない。

## 2. スコープ

### 2.1 MVP に含む

- iOS ネイティブアプリ (iPhone)
- 対応エリア: 全国 (旅行先含む) — ローリングキャッシュ方式
- トリガー: 緊急地震速報 (EEW) での予告起動 + 津波警報・注意報での本起動
- 案内: 地図表示 (MapLibre) + オフライン音声案内 (AVSpeechSynthesizer)
- 発災時の完全オフライン動作 (プッシュ受信以外は通信不要)

### 2.2 MVP に含まない (v2 以降)

- ストリートビュー風の画像案内 (Mapillary 等の事前キャッシュ)
- Android 版
- Apple Watch 対応
- 家族の位置共有・安否確認
- Critical Alerts entitlement (申請は並行して進めるが、MVP は通常通知 + 音量最大再生で成立させる)

## 3. トリガー仕様

### 3.1 段階起動モデル

```
EEW 受信 (予告)            津波警報/注意報 (本番)         解除
     │                          │                      │
     ▼                          ▼                      ▼
ウォームアップフェーズ    →    案内フェーズ        →   終了通知
- BG で現在地取得            - 計算済みルートで
- 経路を事前計算               即時に音声案内開始
- ローカルデータ検証         - 地図に単一経路を表示
- 「津波情報確認中」通知
```

- EEW で警報に至らなかった場合は解除通知を出しウォームアップを破棄する。
- ウォームアップは誤報コストが低い (ユーザーに行動を要求しない) ため、閾値は緩めに設定できる。

### 3.2 電文種別

| 電文 | 用途 |
|---|---|
| VXSE43 / VXSE45 (EEW) | ウォームアップ起動 |
| VTSE41 (津波警報・注意報等) | 案内フェーズ起動 / 解除 |
| VTSE51 (津波情報) | 到達予想時刻の音声更新 |

### 3.3 配信経路

- **一次: DMDATA.jp** — WebSocket 常時接続をサーバー側で維持し、APNs high priority push に変換。EEW の低遅延要件を満たす唯一の現実解。個人契約可。
- **二次 (フォールバック): 気象庁防災情報 XML** — ATOM フィードのポーリング (無料)。DMDATA 障害時の縮退運用。
- **前提認識**: 端末標準の ETWS (エリアメール/緊急速報メール) より自前プッシュは数秒遅れる。本アプリは「公式警報の後追いで自動的に避難準備を整える係」であり、一次警報手段の代替ではない。この位置づけをアプリ内表記・ストア説明にも明記する (App Store 審査対策も兼ねる)。

## 4. 機能要件

### 4.1 平時 (セットアップ・データ管理)

- FR-01: 初回起動時に位置情報 (Always)・通知の許可を、必要性の説明付きで取得する
- FR-02: 現在地周辺の地域データパッケージ (道路グラフ・標高・避難場所・地図タイル) を自動 DL する
- FR-03: significant location change を検知し、移動先地域のパッケージを Wi-Fi 優先で先読みする (ローリングキャッシュ)
- FR-04: 全国分の最小データセット (津波浸水想定区域ポリゴン + 指定緊急避難場所座標 + 粗密度 DEM) をアプリに同梱する
- FR-05: 登録地点 (自宅・職場等) の周辺データは削除対象から除外し常時保持する
- FR-06: データ鮮度を管理し、サーバー側パッケージ更新時に差分 DL する
- FR-07: 避難訓練モード — 任意のタイミングで案内フローをフル体験できる (実データ・実経路を使用)

### 4.2 発災時 (案内)

- FR-10: EEW プッシュ受信でバックグラウンド起動し、現在地取得 → 経路計算 → 「津波情報確認中」通知を表示する
- FR-11: 津波警報・注意報の受信で案内を開始する。通知タップまたはアプリ起動の瞬間に、経路 1 本が地図に表示され音声が流れている状態にする
- FR-12: 経路探索は「最短」ではなく「浸水リスク最小 + 迷いにくさ」を優先する
  - 浸水想定区域内・海方向・河川沿いの経路コストを重くする
  - 標高の増加勾配をコストに組み込む (低い方へ向かう経路を罰する)
  - 曲がり回数の少ない経路を優先する
- FR-13: 音声案内は画面を見ずに完走できる粒度で行う (「次の角を右」「この坂を登り切る」)。サイレントスイッチ・画面ロック状態でも再生し、アプリ内の再生音量は最大とする
  - 当初は「音量は端末設定に関わらず最大で再生する」としていたが、iOS ではシステム音量をアプリから変更できない (`AVAudioSession.outputVolume` は読み取り専用、「Only the user can directly set the system volume」) ことが確認されたため上記に緩和した。根拠と代替手段の検討は [ADR-0007](adr/0007-voice-guidance.md)
- FR-14: 経路逸脱を検知したら 3 秒以内にリルートし音声で通知する
- FR-15: 詳細データ未取得地域では縮退モードで動作する — 浸水域の外周方向 + 最寄り避難場所へのコンパス案内 (方角 + 距離の音声)
- FR-16: 目的地到達を検知し、到達後は「その場に留まる」「解除まで待つ」旨を案内する
- FR-17: 津波情報 (VTSE51) の続報を受信できた場合は到達予想時刻を音声で反映する (受信できなくても案内は継続する)

### 4.3 明示的な非機能スコープ

- 案内フェーズはネットワーク完全途絶で全機能が動作すること (プッシュ受信済み以降、通信を一切要求しない)

## 5. 非機能要件

| ID | 項目 | 目標 |
|---|---|---|
| NFR-01 | プッシュ遅延 | DMDATA 受信 → APNs 送出まで p99 < 1 秒 (サーバー側) |
| NFR-02 | 起動性能 | 通知タップ → 経路表示 + 音声開始まで < 2 秒 (ウォームアップ済み時) |
| NFR-03 | 経路計算 | コールドスタートでも現在地から経路確定まで < 5 秒 (端末内計算) |
| NFR-04 | ストレージ | 1 地域パッケージ < 150MB / 同梱最小データセット < 50MB |
| NFR-05 | バッテリー | 平時の常駐消費は 1 日 2% 未満 (significant location change ベース、常時 GPS 禁止) |
| NFR-06 | 可用性 (サーバー) | 検知〜配信系は multi-region。ただし端末は「サーバー全損でも ETWS で気付いた人が手動起動すれば案内できる」こと |

## 6. アーキテクチャ概要

```
[気象庁] → [DMDATA.jp WS] → [検知サーバー (Go / Cloud Run)] → [APNs]
                                      │
[国土数値情報 / 地理院 DEM / OSM] → [データパイプライン] → [地域パッケージ (GCS 配信)]

iPhone:
  OS API 層   : Core Location / UserNotifications / AVSpeechSynthesizer / BackgroundTasks
  ドメイン層   : 経路探索 (標高コスト付きグラフ探索) / 案内文生成  ← 純粋関数・TDD 対象
  ストレージ層 : GRDB (SQLite) / MBTiles / 同梱最小データセット
  UI 層       : SwiftUI + MapLibre Native
```

通信が発生するのは「平時のパッケージ DL」と「発災時のプッシュ受信」のみ。

## 7. データソース

| データ | ソース | 用途 |
|---|---|---|
| 指定緊急避難場所 (災害種別: 津波) | 国土地理院 オープンデータ | 目的地 |
| 津波浸水想定区域 | 国土数値情報 (A40) | 経路コスト / 縮退モード判定 |
| 標高 (DEM5A/10B) | 地理院 標高タイル | 経路コスト / 高台判定 |
| 道路ネットワーク | OpenStreetMap | 経路グラフ |
| 地図タイル | OpenStreetMap → 自前 MBTiles 生成 | オフライン地図表示 |
| 警報電文 | DMDATA.jp / 気象庁防災情報 XML | トリガー |

## 8. リスクと制約

| リスク | 影響 | 対応 |
|---|---|---|
| APNs 遅延・不達 (silent push 間引き) | T1 悪化 | alert push (high priority) を使用。ETWS 補完の位置づけを明確化 |
| Critical Alerts 審査却下 | サイレントモード非貫通 | MVP は通常通知で成立する設計。承認され次第強化 |
| App Store 審査 (災害系アプリの表現規制) | リリース遅延 | 「公式警報の代替ではない」を明記。医療・安全カテゴリのガイドライン準拠 |
| OSM データ品質 (階段・私道・実際は通れない道) | 誤案内 | 訓練モードでの実地検証を開発プロセスに組み込む |
| 避難場所データの陳腐化 | 誤誘導 | 更新日時をパッケージに埋め込み、6 ヶ月超は UI で警告 |
| 誤報・過剰通知による通知オフ | アプリ無力化 | ウォームアップと本警報の通知強度を明確に分離 |

5. サーバー側の multi-region 構成と APNs 送出のファンアウト設計
